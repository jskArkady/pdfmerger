# PDF 병합기

브라우저에서 여러 PDF 파일을 하나로 합치는 단일 페이지 앱입니다. 자체 PDF 파서를 사용하며, 별도 서버 처리나 외부 라이브러리, 빌드 과정 없이 정적 파일만으로 동작합니다. 선택한 PDF는 브라우저 안에서 읽고 병합합니다.

## 사용 방법

1. `index.html`을 브라우저에서 엽니다.
2. PDF 파일을 선택하거나 화면에 끌어다 놓습니다.
3. 병합할 순서를 조정합니다.
4. `PDF 병합` 버튼을 누릅니다.
5. 저장 위치를 선택하거나, 브라우저 다운로드로 `merged.pdf`를 받습니다.

로컬 서버로 실행하려면 프로젝트 루트에서 다음 명령을 사용할 수 있습니다.

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

이후 브라우저에서 `http://localhost:8000`을 엽니다.

GitHub Pages에서는 배포할 브랜치의 루트(`/`)를 게시 대상으로 선택하면 됩니다. `.nojekyll`로 정적 파일을 그대로 게시하며, CSS와 JavaScript는 상대경로로 불러와 `/pdfmerger/` 같은 프로젝트 하위 주소에서도 동작합니다.

## 기능

- 여러 PDF 파일 선택
- 드래그 앤 드롭으로 파일 추가
- 파일별 페이지 수 표시
- 드래그, 위/아래 버튼으로 병합 순서 변경
- 파일명, 파일 크기, 페이지 수, 추가순 정렬
- 브라우저 안에서 병합 PDF 생성
- File System Access API 지원 브라우저에서는 저장 위치 선택
- 그 외 브라우저에서는 `merged.pdf` 자동 다운로드
- 파일을 읽는 동안 변경한 정렬·삭제 상태 유지
- 병합·저장이 끝날 때까지 목록 변경과 중복 병합 방지

## 보안 동작과 지원 범위

선택한 파일은 브라우저 메모리에서 처리하고, 외부 업로드나 브라우저 영구 저장을 하지 않습니다. CSP로 스크립트의 네트워크 연결과 외부 리소스 로딩을 제한합니다. 저장창에서 원본 경로를 선택하면 원본을 덮어쓸 수 있으므로 별도 파일로 저장하세요.

최종 `startxref` 및 `/Prev` 연결에서 유효한 객체만 읽습니다. 일반 xref, xref stream, hybrid-reference, 압축 객체의 type-2 참조를 지원합니다. 객체 번호·세대·위치·크기·중복 키·페이지 트리를 검증하고, xref가 가리키지 않는 객체나 이전 버전의 삭제된 객체를 복구하지 않습니다. 손상된 PDF는 병합을 중단합니다.

출력은 페이지 트리에서 필요한 객체만 새로 작성합니다. 원본 Catalog, 문서 Info, 미참조 객체, 페이지·XObject 등의 Metadata/PieceInfo를 제외하고 문자열과 페이지 스트림의 바이트를 보존합니다. **이는 개인정보 마스킹이나 완전한 비식별화 기능이 아닙니다.** 페이지 내용, 이미지, 글꼴 또는 사용자 정의 데이터에 포함된 정보는 결과에 남을 수 있습니다.

다음 기능이 있는 PDF는 해당 기능을 제거한 결과 대신 오류를 표시합니다.

- 암호화·비밀번호 보호
- 링크를 포함한 PDF 동작, 자동 동작, JavaScript, 외부 파일 참조
- 첨부 파일, 양식, 전자서명, 숨은 레이어, 멀티미디어, PostScript XObject, OPI
- 문서 전체 출력 색상 설정(`/OutputIntents`, 일부 PDF/A·인쇄용 문서 포함) 또는 추가 렌더링이 필요한 문서

일반 페이지의 이미지·내용 스트림은 압축 상태 그대로 복사합니다. 파서가 직접 읽어야 하는 object/xref stream은 무압축 또는 단일 `/FlateDecode`만 지원합니다. 해당 스트림의 예측 필터는 8비트 TIFF 및 PNG 형식을 지원하며, 그 외 필터·파이프라인·예측 형식은 오류 처리합니다. xref stream의 `/Length`는 직접 정수여야 합니다. 일반 스트림의 간접 `/Length`는 유효 xref를 통해 해석합니다.

압축 해제 시 Huffman 코드, 길이·거리, 블록 종료, 입력 경계와 zlib 체크섬을 검사합니다. 입력은 최대 50개, 파일당 25 MiB, 전체 100 MiB이며 파일 읽기는 동시에 2개까지만 수행합니다. 추가 한계는 `PdfMerger.LIMITS`에 모여 있습니다.

| 항목 | 한계 |
| --- | --- |
| 개별 디코딩 결과 | 32 MiB |
| 작업 전체 디코딩·예측 변환 누적 | 64 MiB |
| 문서 xref Size/객체 수 | 100,000 |
| 중첩·객체 해석·페이지 트리 깊이 | 128 |
| xref 섹션 수(hybrid 포함) | 128 |
| 파서·해제·탐색 작업량 | 2,000,000회 |
| 병합 결과 | 128 MiB |
| 분석 또는 병합 작업 기한 | 10초(처리 루프에서 검사) |

한계를 초과하면 결과 파일을 저장하지 않습니다. 메모리 사용량은 입력 크기보다 클 수 있고, 분석과 병합은 동기 처리이므로 큰 파일에서 UI가 잠시 응답하지 않을 수 있습니다. 위 수치는 모든 크기의 PDF 처리를 보장하는 값이 아니며 구조가 복잡하면 더 일찍 중단될 수 있습니다.

## 파일 구조

```text
.
├── index.html
├── styles.css
├── .nojekyll
├── src/
│   ├── app.js             # 파일 목록, 화면 갱신, 저장 처리
│   └── pdf-merger.js      # PDF 분석, 압축 해제, 병합 및 출력
└── tests/
    ├── pdf-fixtures.js    # Node.js와 브라우저에서 공유하는 테스트 PDF 생성기
    ├── test-app.html      # 실제 브라우저 UI 회귀 테스트
    ├── test-pdf-merger.cjs
    └── test-security.cjs
```

## 테스트

Node.js가 설치되어 있으면 병합 로직 테스트를 실행할 수 있습니다.

```sh
node tests/test-pdf-merger.cjs
node tests/test-security.cjs
```

문법 검사는 다음 명령을 사용합니다.

```sh
node --check src/pdf-merger.js
node --check src/app.js
node --check tests/pdf-fixtures.js
node --check tests/test-pdf-merger.cjs
node --check tests/test-security.cjs
```

UI 회귀 테스트는 위의 로컬 서버를 실행한 다음 `http://localhost:8000/tests/test-app.html`을 브라우저에서 엽니다. 파일 읽기 완료 순서, 정렬·삭제, 크기·개수 제한, 동시 읽기, 위험 PDF 거부, 저장 취소·오류, 다운로드 결과와 CSP를 검사합니다. 저장 선택창과 다운로드 시작은 테스트에서 대체하므로 OS 저장창의 실제 동작은 별도로 확인해야 합니다.

보안 회귀 테스트는 유효 xref 선택, 미참조 데이터 제외, 주석 포함 참조, 간접·이스케이프 이름, 숫자 원문, hybrid/압축 xref, PNG 예측 필터, 정상·손상 압축 데이터를 확인합니다. 무한 반복 회귀는 제한 시간이 있는 자식 프로세스에서 검사하며 실제 개인정보나 네트워크 전송을 사용하지 않습니다.
